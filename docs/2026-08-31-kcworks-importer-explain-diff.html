Why the JCRT KCWorks importer now fails safely

The change does not redesign the importer. It makes one copy canonical, gives a long upload a finite boundary, preserves evidence, and ensures that “anything except complete success” stops the surrounding publication workflow.

Python 3.9+ requests HTTP 201 = success 6 focused tests

Background

The beginner’s model: a deposit is a consequential POST

JCRT stores each article as Markdown plus front matter in jcrt-v2. A generator in jcrt-meta turns one issue into a JSON metadata array and a ZIP of PDFs. The wrapper then sends both to the KCWorks streamlined import endpoint. KCWorks may create public records and mint DOIs, so this POST is not an operation that can be repeated casually.

KCWorks is built on InvenioRDM and adds a streamlined bulk-import workflow documented in the KCWorks API reference. The former explains the repository platform; the latter is the contract this importer follows.

sourceMarkdownnanoid: T4s4RL
derivedJSON + ZIPimport-recid: T4s4RL
remoteKCWorksrecord + DOI
returnFront matterdoi: 10.17613/…

The shell wrapper continues to DOI synchronization only when the Python process exits successfully. That makes the importer’s exit code part of the data-integrity boundary: a false zero can make a partial or failed remote operation look complete.

The narrow problem: the old client had six sharp edges

HIGH207 and 500 could exit zeroThe wrapper could continue after partial or total failure.
HIGHNo timeoutA stalled request could wait indefinitely.
HIGHURL override disabled TLS checksAn HTTPS test or alternate endpoint silently lost certificate verification.
MEDIUMBoundary JSON was trustedBad input reached the server; non-object output could crash formatting.
MEDIUMTwo importer copiesThe wrapper and documentation could drift to different behavior.
LOWSpinner threadCosmetic output added concurrency and cleanup code.
Key term: ambiguous outcomeA client timeout says only that the client stopped waiting. The server might have failed, might still be working, or might already have created records. Therefore timeout handling must say “reconcile before retrying,” not “safe to retry.”

Intuition

Imagine depositing three articles: A, B, and C. The only green path is a response that says all three were created and arrives as HTTP 201. Every other path must preserve what the server said and stop.

requestA + B + Cone multipart POST
evidenceSave responsedata, errors, IDs
decisionExactly 201?not “JSON parsed?”
next stepSync or stopzero or nonzero exit

A toy 207 response might report A and B as created while C failed validation. Retrying A, B, and C can duplicate A and B. The correct response is to save the result, stop automation, and reconcile each stable import-recid. The same caution applies when the client times out before receiving any response.

The implementation follows one simple rule:

Preserve first, decide second.Parse or retain the response body, write it to the requested output path, display the useful message, and only then return success for HTTP 201 or failure for everything else.

Code walkthrough

1. One canonical importer

The repository had a root copy and an attributed copy under scripts/. The root copy had already diverged. The wrapper now calls the script copy and the duplicate is deleted.

Before

"$python" kcworks_api_importer.py \
  --collection-id "$slug" ...

After

"$python" scripts/kcworks_api_importer.py \
  --collection-id "$slug" ...

2. Validate local metadata before network access

The API requires an array of record objects. The importer now checks JSON syntax and the array root locally, before it opens the network boundary.

Before

with open(metadata_path) as metadata_file:
    metadata_json = metadata_file.read()

# Sent without parsing

After

with open(metadata_path, encoding="utf-8") as metadata_file:
    metadata_json = metadata_file.read()
try:
    metadata = json.loads(metadata_json)
except json.JSONDecodeError as error:
    _print_error("Metadata is not valid JSON", str(error))
    sys.exit(1)
if not isinstance(metadata, list):
    _print_error("Metadata JSON must contain an array at its root")
    sys.exit(1)

3. Bound the request without pretending it is idempotent

requests accepts a pair of timeout values. Connection establishment gets 10 seconds; reading the potentially slow import response gets 600 seconds by default and can be changed with --timeout or KCWORKS_IMPORT_TIMEOUT.

response = requests.post(
    api_url,
    headers=headers,
    files=files,
    data=data,
    verify=not testing,
    timeout=(DEFAULT_CONNECT_TIMEOUT, timeout),
)

A timeout exits nonzero with an explicit warning that the server outcome is unknown. There is no automatic POST retry.

4. Keep TLS verification tied to explicit test mode

Previously, merely setting KCWORKS_IMPORT_API_URL disabled verification. Now endpoint selection and transport security are separate decisions: a URL override changes the destination; only --testing changes verify to false.

Before

if api_url_env:
    api_url = ...
    verify_ssl = False

After

api_root = api_url_env or default_api_root
api_url = f"{api_root.rstrip('/')}/{collection_id}"

# In requests.post(...)
verify=not testing

5. Save evidence, then enforce the 201 contract

JSON is not automatically trustworthy because it parsed. The formatter expects an object, so lists, strings, and other JSON roots now take the same safe path as malformed JSON: save the raw body and fail cleanly. For an object response, the full JSON is written before the status is judged.

if output_path:
    with open(output_path, "w", encoding="utf-8") as output_file:
        json.dump(response_json, output_file, indent=2)
    print(f"\nFull response saved to: {output_path}")
if response.status_code != 201:
    sys.exit(1)

6. Remove cosmetic concurrency and make ownership lexical

The spinner thread did not make the upload faster or safer. A static progress line replaces it. ExitStack owns every open upload file and closes them together when the request scope ends, including exceptional paths.

Before

file_handles = []
stop_spinner = threading.Event()
spinner_thread = threading.Thread(...)
...
finally:
    for file_handle in file_handles:
        file_handle.close()

After

with ExitStack() as stack:
    files = [
        ("files", (name,
          stack.enter_context(open(path, "rb")), mime))
        for path in files_paths
    ]
    print("\nImporting records...")
    response = requests.post(...)

Behavior matrix

HTTP 201 + object JSONPrint and save response; exit 0; wrapper may synchronize DOIs.
HTTP 207 / 4xx / 5xxPrint and save response; exit 1; reconcile before further action.
Client timeoutExit 1; outcome unknown; inspect submitted import-recid values before retrying.
Malformed metadataExit 1 before calling requests.post.
Non-object responseSave raw body when an output path exists; exit 1 without formatter crash.
HTTPS URL overrideCertificate verification remains enabled unless explicit test mode is active.

Three observed HTTP 500 responses carried diagnostic IDs e54e719e13cc441ba699b26e40e5acd4, 80e109ecb7cf4f099744e780d42f6395, and 91058a2074ed423fa81be180fe15c203. Those were server responses, not client-side timeout exceptions. Keeping the categories separate is essential because one has a response body to preserve while the other has an unknown outcome to reconcile.

Deliberately absentNo retry decorator, batching framework, duplicate detector, or local copy of the full KCWorks schema was added. Retries require idempotency; batch recovery requires JCRT-specific reconciliation; KCWorks remains authoritative for its schema.

Verification

The check suite makes no live KCWorks requests. A mocked response object exercises the important branches while the existing issue preflight verifies the wrapper path and generated payload.

python3 -m py_compile scripts/kcworks_api_importer.py
.venv/bin/python -m unittest discover \
  -s scripts -p 'test_kcworks_api_importer.py'
.venv/bin/python scripts/kcworks_api_importer.py --help
./import.sh --check 25.1
rg -n 'kcworks_api_importer\.py' README.md import.sh scripts CHANGELOG.md
git diff --check

The six focused tests cover HTTP 201, HTTP 207 and 500, timeout warnings, invalid metadata before request, malformed or non-object responses, and TLS verification for an overridden HTTPS endpoint.
